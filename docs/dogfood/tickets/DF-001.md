# DF-001: Preserve project navigation in the URL

Priority: P1. Source: hands-on dogfooding on 2026-09-14.

## Problem

Opening a project and selecting Conversations leaves the URL at `/`. Reloading
returns to the board and loses the selected project and tab. Developers cannot
bookmark a review or open the same project in a second browser tab.

## Requested behavior

Add lightweight URL-backed navigation to the existing app, preserving the
current design. A hash-based route is acceptable; no routing dependency is needed.

## Acceptance criteria

1. Opening a project and switching among Overview, Plan, Conversations, Review,
   and Terminals updates the URL to identify the project and selected tab.
2. Reloading or opening that URL in another tab restores the selected view after
   the asynchronous snapshot loads.
3. Browser Back and Forward work between board, project, and project tabs.
4. Repositories, Skills, and Settings can also be reloaded without returning to
   the board.
5. Missing project IDs and malformed routes fall back to a usable board with an
   understandable message, without an exception or redirect loop.
6. Unsaved plan/review feedback is not stored in the URL. No changes to workflow
   approval gates, publication, model configuration, or unrelated behavior.
7. Add meaningful automated coverage for route parsing and navigation logic;
   run `npm run check`, relevant tests, and `npm run build`.

Keep all implementation inside the managed project worktree. Do not commit,
push, create a PR, or modify global settings. Do not delegate to other agents.

The ticket is served as plain text over a local HTTP endpoint. If web fetching
does not support loopback, retrieve this exact URL with a read-only shell HTTP
client, such as `curl.exe --fail http://127.0.0.1:4331/DF-001`.
